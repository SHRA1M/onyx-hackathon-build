## What to build: `python -m onyx site` writes `docs/site/`

Static HTML, inline CSS and JavaScript, no framework, no npm, no build step, no network call at view time, opens from
`file://`. Same visual language as `docs/replay/index.html` (reuse its CSS and helpers from `replay_viewer.py`;
refactor shared code into one module rather than copying it). Arabic text with `lang="ar"` and `dir="rtl"`, as the viewer does.

Pages, all linked from a header bar:

1. `index.html`: Mizan in one screen. The notice line ("The operator, subscribers and numbers are synthetic; the law
   texts are real, linked and hashed."). The headline figures from `eval/results.json` (C5 governed: citation
   validity, action recall, abstention, gap recall, en / ar; C3: ungoverned claims allowed, gate rejection), each
   with the label the report uses and the definition from `eval/results.md` in a hover or footnote. Counts from the
   manifest (documents, VERIFIED, REFERENCED, UNVERIFIED). The sentence: "A quote that is not word for word in a
   verified clause is rejected before it reaches the subscriber." Links to the four pages below and to the repo.
2. `runs.html`: the existing replay viewer, as it is (or `index.html` of `docs/replay/` moved here and the old path
   kept as a redirect or copy; the build chooses; tests on the old path keep passing). Add to each run's header a
   "Verify this log" button (page 5).
3. `gaps.html`: the 11 register rows plus the candidates, rendered from `onyx/data/gaps.json` the way `docs/gaps.md`
   is: gap, kind, addressee, searched clauses with what each says (English and Arabic where the chunk holds it), UAE
   position, recommendation, global examples with their verbatim quotes and file names. Row order as the report.
4. `kb.html`: the manifest as a table: document_id, title (and title_ar), issuer, instrument, language, status,
   binding_status, sha256 (full, in a monospace cell), url (a link), notes. Counts at the top. Filter buttons by
   status and by language, in JavaScript, client side.
5. `verify.html` (or a panel on `runs.html`): the judge picks a run (all 60 governed and ungoverned C3, C4, C5 runs
   listed) and the page recomputes the chain in the browser with WebCrypto SHA-256: for each event,
   `sha256(prev_hash + canonical_json(event without "hash"))` as `onyx/audit.py` defines it, and shows per event
   whether the stored hash matches, then the final hash. Also prints the equivalent command
   (`python -m onyx replay <path>` or whatever the audit command is) for a judge who prefers the terminal.
   **Canonical JSON must match Python byte for byte** (`sort_keys=True`, `ensure_ascii=False`, separators `,` and
   `:`). Watch floats (Python writes `1.0`, JavaScript `1`) and string escaping. Write a Python test that runs the
   JavaScript canonicalisation through Node if Node is on the machine, or that checks every event in the 60 logs
   has no value whose JSON form would differ (no float with an integral value, no character JavaScript escapes
   differently). If it cannot be made exact for every event: stop and ask, with the first differing event.
6. `whatif.html`: S2 under the rule gap 1 recommends, as the viewer's what-if section shows it, side by side with the
   recorded run: the step that releases, the clock the duty gains, the finding that the hand-over time is not logged.

The run and figure selection rules of `replay_viewer.py` (module docstring) apply unchanged. No number on any page
is typed in source; every one is read from `eval/results.json`, the logs or the manifest.
