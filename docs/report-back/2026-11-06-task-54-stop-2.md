### 1. S4-3: the ruling's class and main-text clause are false

Ruling, class: "the gate blocked a proposal that cut incoming calls, which 22.3 forbids; the key's allow assumes the confined scope". Ruling, S4 line: "blocked in Arabic, where the proposal also cut incoming calls (22.3)". Section A: "model widened the scope in Arabic".

Both Arabic proposals, as recorded (`runs/c5/S4/ar/run1.jsonl`; run2 has the same `kept` and `scope`):

```
"kept": ["المكالمات الواردة", "أرقام الطوارئ", "النطاق العريض المنزلي"]
"scope": ["المكالمات الصادرة", "البيانات على الخط المحمول"]
```

That is incoming calls, emergency numbers and home broadband kept; outgoing calls and mobile data interrupted. It is the same scope as the English proposals, which were allowed. The rationale in ar1 says the same.

The log's reasons on both Arabic blocks: "incoming calls, a basic non-substitutable service, are cut (22.3)" and "emergency numbers are not kept reachable (22.4)". Both are false against the proposal. Cause, `onyx/gate.py:552`:

```python
kept = read_items(p.args.get("kept", []), {"incoming calls", "emergency numbers"})
```

The terms are English only, so the Arabic words do not match. This is the only reason the Arabic runs were blocked at this step and the English runs allowed.

Recommendation: class S4-3 as a field-shape fault in the ruling's words, plus "in Arabic", and "listed for the fix after the shortlist". The diagnosed set becomes four steps (S3-5, S4-3, S5-5, S5-6), so the README's "three" becomes "four". Task 55's list gains this item. The ruling's summary for Iyas ("three of those... the rest are the gate being stricter") changes too.

A reader may also ask whether other gates read Arabic this way. I did not survey that.
