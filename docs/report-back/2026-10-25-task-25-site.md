## Summary

`python -m onyx site` writes `docs/site/`: six static pages that open from file:// with no server, no network call
and no key. Every figure, row and quote is read from the committed files by plain code; CI regenerates the pages and
fails on any byte difference.

- `index.html`: the notice, the sentence, C5 citation validity, action recall, abstention and gap recall (en / ar);
  C3 claims allowed ungoverned (en / ar) and gate rejection by scenario (min to max); manifest counts; each figure
  footnoted to its definition, read from `eval/results.md`.
- `runs.html`: the replay viewer with the site bar and a "Verify this log" button on every run (governed and the
  ungoverned run beside it).
- `gaps.html`: the 13 register rows (11 gaps, 2 candidate rows) and the 4 candidates, with clauses searched (EN and
  AR where the chunk holds it), UAE position, standard text, global examples with quote and file, recommendation.
- `kb.html`: the 50 manifest rows, full sha256 in monospace, status and language filters (client side).
- `verify.html`: pick any of the 100 C3, C4 and C5 logs; the page recomputes every event's hash with WebCrypto, shows
  stored against recomputed per event and the final hash, and prints `python -m onyx verify-log <path>`.
- `whatif.html`: S2 C5 run 1, recorded against the gap-1 rule, decision by decision: the S2-3 block gains the
  two-minute clock, the S2-5 hold becomes an allow, and the finding that the hand-over time is not logged.

## What differs from the order, and why

- **100 logs, not 60.** The order's "all 60 governed and ungoverned C3, C4, C5 runs" was hq's miscount: C3 alone is 60
  (30 governed, 30 ungoverned), and C4 and C5 add 20 each. Iyas approved 100 on 2026-10-25.
- **The float trap was real and is solved, not stopped on.** Three of 2,104 events hold a whole-number float
  (`model_ms` 10447.0, 6555.0, 4509.0). JSON.parse turns 10447.0 into 10447 and those three hashes fail. The page
  reads each log with a small parser that keeps every number as the log wrote it; strings and keys go through
  JSON.stringify, keys sort by code point. Approved by Iyas before the build. One consequence: a number rewritten in
  an equivalent form (10447.00) fails in the browser and passes in Python; stricter, never looser.
- **runs.html is a second render of the viewer**, not a move: `docs/replay/index.html` stays where it is,
  byte-identical, so no test changed. The what-if link inside runs.html points to `../replay/`.
- **Gap row order:** the report's gap table order (1, 2, 3, 4, 5, 6, 11, 8, 9, 10), read from `docs/report.md`; gap-7,
  absent from the report's table, and the two candidate rows follow in register order.
- **Screenshots by headless Chrome**, not Python Playwright (not installed; no new dependency).
