# onyx-hackathon-build: background

Updated 2026-10-21 (eleventh wrap, Opus: Task 8 Part C1 prompt v2 and C2 finding test and v2 bake-off; waiting for Iyas's go on C3).

## What this is

Mizan, team Onyx's entry to the ITU AI for Good Lab Hackathon UAE 2026 (telecom T1). Agents propose JSON actions; plain-code gates decide from clauses of binding UAE text; every step goes to a hash-chained log. Orders: `docs/work-orders/2026-10-17-onyx-mizan.md`, then `2026-10-21-task-8-live.md` (Parts A and B done), then `2026-10-21-task-8-part-c.md` (C1 and C2 done; C3, the scored Sonnet run, waits for Iyas's go). Thinking and business facts: `D:\Projects\hq\uni\ai-for-good-hackathon\`. Submission 2026-11-09.

## Stack and how it runs

Python 3.12 (uv), ChromaDB 1.5.9 (default embedding all-MiniLM-L6-v2, 79 MB, downloaded once), pytest, jsonschema, pypdf. CLI: `python -m onyx kb fetch|verify|chunk|ingest|export`, `python -m onyx check-data`, `python -m onyx verify-log <file>`, `python -m onyx run S1..S5 [--lang ar] [--ungoverned] [--inject TEXT]` (scripted, offline), `python -m onyx record --source scripted|live [--root DIR] [--modes governed ungoverned] [--runs N] [--max-usd 5] [--skip-existing]`, `python -m onyx bakeoff [--out eval]` (v1 and v2 tables from `bakeoff.VERSIONS`), `python -m onyx selftest` (S1 offline, no key, headline figures), `python -m onyx replay <log>`, `python -m onyx eval --runs <root> --out <dir>`. Live model: `.env` at the repo root (gitignored) with ONYX_MODEL_BASE_URL, ONYX_MODEL, ONYX_MODEL_API_KEY; names in `.env.example`. The process environment overrides `.env` per name, so `ONYX_MODEL=claude-sonnet-5-5 uv run python -m onyx record ...` picks a model without editing `.env`. `ONYX_SOURCE_DIR=D:\Projects\hq\uni\ai-for-good-hackathon` lets `kb fetch` fall back to the hq copies and `kb chunk` read the hq text extractions (maintainer only); the CPR Arabic it reads from the PDF with pypdf, because the hq .txt files (made with PyMuPDF) reverse the lam-alef. Remote: github.com/SHRA1M/onyx-hackathon-build, private, branches main and backup/main, CI `reproduce.yml` (kb fetch, kb verify, check-data, pytest). Not hosted; no push deploys.

## Traps

- The spend guard estimates from the medians of recorded calls, mostly prompt v1; v2 prompts are about twice as long (Haiku 1.96x prompt tokens, Sonnet cost 1.36x). The guard under-estimates v2 runs: project from `runs/bakeoff-v2` costs and run in slices with a spend check between them.
- Opus 5.5 through the OpenAI-compatible endpoint returns `finish_reason: content_filter` on most of our consumer-care prompts (empty or cut replies); `parse_output` reads them as unparseable. Check finish reasons before reading a parse-failure count.
- A live run that dies leaves a partial log that blocks a re-run. Move it to `runs/bakeoff/_failed/` (or the matching `_failed` folder) so its spend still counts, then `record ... --skip-existing`. Background `record` buffers stdout: run it with `python -u` to see the estimate line.
- The ChromaDB index (`data/chromadb`, gitignored) goes stale after any `kb chunk`: live retrieval then returns clause ids not in `kb/chunks` and the run dies (KeyError). Run `python -m onyx kb ingest` after every `kb chunk`. Rebuilt 2026-10-21 (106 in kb_main).

- A new rule citing an uncited clause: run `kb chunk` with `ONYX_SOURCE_DIR` set, read the clause in `kb/chunks-full/`, add the rule, run `kb chunk` again so `kb/chunks/` picks it up. Then `git checkout -- kb/chunks/licence-2-2026.jsonl` and `kb/chunks/tdra-cpr-v2-en.jsonl`, and re-apply the hand fixes (next item).
- A `kb chunk` rebuild undoes hand fixes in committed chunks: licence 3.4.1 'pur suant' and 9.1 'billin g' (pypdf errors; the committed file has them right), and the CPR 4.7.3 'opt-out' and 24.7 'anti-competitive' (the extraction keeps 'opt- out', 'anti- competitive'). Licence 9.3 now matches the rebuild. Never commit a rebuilt licence or CPR file unchanged.
- `check-data` compares quotes with our chunks, not with the PDFs. The 2026-10-21 pdftotext audit found 13 of 110 quotes not verbatim in pdftotext output (8 layout only); see the report-back.
- `kb fetch` rewrites `url_accessed` and `http_status` in the manifest to the run's date: do not commit a manifest changed only by a fetch.
- The UAE legislation portal answers 403 to scripts; Y.3172 and EUR-Lex URLs are pages, so their bytes never match.
- PyMuPDF and pdfium reverse the lam-alef on TDRA and portal Arabic text layers; pypdf and pdftotext keep it. The hq .txt files are PyMuPDF output (except the licence, re-extracted with pypdf 2026-10-21): re-extract with pypdf before chunking any other Arabic source. pdftotext adds bidi control marks.
- pdftotext on this machine is xpdf 4.00 (`/mingw64/bin`), not poppler: CRLF line ends, and it writes math-alphabet letters as split surrogates (QoS); decode with `surrogatepass`.
- `طالما` and `ثالث` are real words: do not add them to the broken-word list.
- The IMDA text is Windows-1252; `kb.read_text` falls back.
- Y.3172 needs `top` headings and a footer strip that splits glued page numbers (`138.1` is page 13 + clause 8.1).
- `.gitattributes` forces LF so hashes match on every machine.
- Git Bash turns `C:/...` arguments into broken paths inside `git filter-branch`; use `/c/...`.
