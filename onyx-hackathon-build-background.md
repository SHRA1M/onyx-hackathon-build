Mizan, team Onyx's entry to the ITU AI for Good Lab Hackathon UAE 2026 (telecom T1). Agents propose JSON actions; plain-code gates decide from clauses of binding UAE text; every step goes to a hash-chained log. Orders: `docs/work-orders/` in date order, each with its report-back in `docs/report-back/` (the order chain to Task 16 with commits is in the archive, 2026-10-22 twenty-second wrap). ## Stack and how it runs

Python 3.12 (uv), ChromaDB 1.5.9 (default embedding all-MiniLM-L6-v2, 79 MB, downloaded once), pytest, jsonschema, pypdf, matplotlib 3.11.2 (dev, figures only). CLI: `python -m onyx kb fetch|verify|chunk|ingest|export`, `python -m onyx check-data`, `python -m onyx verify-log <file>`, `python -m onyx run S1..S5 [--lang ar] [--ungoverned] [--inject TEXT]` (scripted, offline), `python -m onyx record --source scripted|live [--root DIR] [--modes governed ungoverned] [--runs N] [--max-usd 5] [--skip-existing]`, `python -m onyx bakeoff [--out eval]` (v1 and v2 tables from `bakeoff.VERSIONS`), `python -m onyx selftest` (S1 offline, no key, headline figures), `python -m onyx replay <log>` (prints the hand-over quotes EN and AR), `python -m onyx replay-page [--html]`, `python -m onyx gaps`, `python -m onyx eval --runs <root> --out <dir>`. Live model: `.env` at the repo root (gitignored) with ONYX_MODEL_BASE_URL, ONYX_MODEL, ONYX_MODEL_API_KEY; names in `.env.example`. The process environment overrides `.env` per name, so `ONYX_MODEL=claude-sonnet-5-5 uv run python -m onyx record ...` picks a model without editing `.env`. `ONYX_SOURCE_DIR=D:\Projects\hq\uni\ai-for-good-hackathon` lets `kb fetch` fall back to the hq copies and `kb chunk` read the hq text extractions (maintainer only); the CPR Arabic it reads from the PDF with pypdf, because the hq .txt files (made with PyMuPDF) reverse the lam-alef. Remote: github.com/SHRA1M/onyx-hackathon-build, private, branches main and backup/main, CI `reproduce.yml` on push (uv sync, kb verify, check-data, pytest, selftest, verify-log on every committed log, replay S1 to S5, eval live and scripted, gaps, replay-page, replay-page --html, both figure scripts, `git diff --exit-code`; no kb fetch, no secret; badge in README). Not hosted; no push deploys.

## Traps

- Every Y.3172 chunk carries page 1 (chunker quirk); a gap row gives its own `page`. `kb/sources/global/` is gitignored, so the verbatim global-quote test skips in CI.

- USD 1.12 is left of the USD 20 prepaid balance: no live run fits a full batch. Any new live run needs Iyas to top up first.
- The Playwright browser tool blocks `file://`: serve `docs/replay` with `uv run python -m http.server` for screenshots (bare `python` is the Store alias).
- `gh run` status lags on GitHub (2026-10-22: a 42 s job showed in progress for 17 min after every step passed); read the job's steps with `gh run view <id> --json jobs`.
- Opus 5.5 through the OpenAI-compatible endpoint returns `finish_reason: content_filter` on most of our consumer-care prompts (empty or cut replies); `parse_output` reads them as unparseable. Check finish reasons before reading a parse-failure count.
- Windows globbing is case-insensitive: `runs/S*` also matches `runs/scripted`. Filter on `Path(p).parts[1]` in S1..S5 or ungoverned.
- A batch loop that pipes a check through `tail` loses its exit code: use `set -o pipefail` or capture `$?` before piping, or a stop rule silently passes.
- A live run that dies leaves a partial log that blocks a re-run. Move it to `runs/bakeoff/_failed/` (or the matching `_failed` folder) so its spend still counts, then `record ... --skip-existing`. Background `record` buffers stdout: run it with `python -u` to see the estimate line.
- The ChromaDB index (`data/chromadb`, gitignored) goes stale after any `kb chunk`: live retrieval then returns clause ids not in `kb/chunks` and the run dies (KeyError). Run `python -m onyx kb ingest` after every `kb chunk`. Rebuilt 2026-10-22 (121 in kb_main).
